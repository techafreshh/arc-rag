# Deployment Fix Summary

## Issues Encountered

### 1. Qdrant Health Check Endpoint Mismatch
**Problem:** The `init.sh` script checked `GET /health` for `"status":"green"`, but the Qdrant instance on the VPS (v1.16.3) uses `/readyz` which returns `"all shards are ready"`.

**Fix in `scripts/init.sh`:**
```bash
# Before
status=$(wget -q -O- "${QDRANT_URL}/health" 2>/dev/null || true)
if echo "$status" | grep -q '"status":"green"'; then

# After
status=$(wget -q -O- "${QDRANT_URL}/readyz" 2>/dev/null || true)
if echo "$status" | grep -q 'all shards are ready'; then
```

### 2. Missing `wget` in Docker Image
**Problem:** `python:3.11-slim` doesn't include `wget`, which `init.sh` uses for health checks and Qdrant API calls.

**Fix in `backend/Dockerfile`:**
```dockerfile
# Added before pip install
RUN apt-get update && apt-get install -y --no-install-recommends wget && rm -rf /var/lib/apt/lists/*
```

### 3. Missing Sitemap Parsing Step
**Problem:** `init.sh` ran `build_index.py` directly, which expects `data/arcpro_urls.json` to exist. The file is generated by `parse_sitemaps.py`, which was never called.

**Fix in `scripts/init.sh`:**
```bash
# Added before build_index.py
echo "[init] Running parse_sitemaps.py (source=${SOURCE})..."
python /app/scripts/parse_sitemaps.py --source "$SOURCE"
```

### 4. Python Import Path in Docker
**Problem:** `load_qdrant.py` adds `PROJECT_DIR / "backend"` to sys.path, but in the Docker container `src/` is at `/app/src/` (not `/app/backend/src/`), causing `ModuleNotFoundError: No module named 'src'`.

**Fix in `scripts/load_qdrant.py`:**
```python
# Before
sys.path.insert(0, str(PROJECT_DIR / "backend"))

# After
backend_dir = PROJECT_DIR / "backend"
sys.path.insert(0, str(backend_dir if backend_dir.exists() else PROJECT_DIR))
```

### 5. Embedding API Transient Failure
**Problem:** `embed_batch()` in `embed.py` failed with `KeyError: 'data'` at 49,400/80,099 vectors — likely a rate limit or transient API error returning an unexpected response.

**Fix in `backend/src/embed.py`:**
```python
# Added retry logic with exponential backoff
async def embed_batch(client, texts, model=None, max_retries=5):
    for attempt in range(max_retries):
        resp = await client.post(...)
        if resp.status_code == 429:
            await asyncio.sleep(2 ** attempt)
            continue
        resp.raise_for_status()
        data = resp.json()
        if "data" not in data:
            raise ValueError(f"Unexpected embeddings response: {data}")
        return [item["embedding"] for item in data["data"]]
    raise RuntimeError(f"Embedding failed after {max_retries} retries")
```

### 6. build_index.py Overwhelming httpx Connection Pool
**Problem:** `build_index.py` used `asyncio.gather(*(process(u) for u in remaining))` spawning ALL 10,548 coroutines at once sharing a single httpx client, causing all requests to fail with "Server disconnected without sending a response".

**Fix in `scripts/build_index.py`:**
```python
# Before: all coroutines at once with shared client
async with httpx.AsyncClient(...) as client:
    await asyncio.gather(*(process(u) for u in remaining))

# After: batched with per-request client and delay before fetch
batch_size = concurrency * 10
for i in range(0, len(remaining), batch_size):
    batch = remaining[i:i + batch_size]
    await asyncio.gather(*(process(u) for u in batch))

# And in process():
async def process(url: str):
    async with semaphore:
        await asyncio.sleep(delay)  # delay BEFORE request
        async with httpx.AsyncClient(...) as client:
            html = await fetch_html(client, url)
```

**Also increased delay from 0.2s to 1.0s in `scripts/init.sh`.**

### 7. Qdrant on Different Docker Network
**Problem:** The existing Qdrant container runs on `localai_default` and `web_gateway` networks. The prod compose creates `arc-rag_default`, so init containers can't reach Qdrant.

**Fix:** User's `docker-compose.override.yml` joins services to the `web_gateway` network where Qdrant lives.

### 8. Health Check HEAD Method Not Allowed
**Problem:** The backend health check used `wget --spider` (HEAD method), but FastAPI's `/health` endpoint only supports GET, returning 405.

**Fix in `docker-compose.prod.yml`:**
```yaml
# Before
test: ["CMD", "wget", "-q", "--spider", "http://localhost:8000/health"]

# After
test: ["CMD", "wget", "-q", "-O", "/dev/null", "http://localhost:8000/health"]
```

### 9. Frontend Port Conflict
**Problem:** Frontend exposed port 3000 on localhost, conflicting with another service (aura-frontend).

**Fix in `docker-compose.prod.yml`:** Changed `ports: ["3000:3000"]` to `expose: ["3000"]` — Caddy reaches the container through the Docker network.

### 10. Stale Checkpoint from Failed Runs
**Problem:** The arcmap build_index checkpoint from earlier failed runs had all 10,548 URLs marked as "done" with 0 pages. On restart, it saw "Nothing to do" and skipped everything.

**Fix:** Deleted the stale checkpoint from the Docker volume:
```bash
docker run --rm -v arc-rag_arcrag_data:/data busybox rm /data/.checkpoint_arcmap_index.json
```

### 11. ArcMap Pages Use Meta-Refresh Redirects
**Problem:** Many ArcMap URLs return 200 with a meta-refresh HTML redirect instead of HTTP 301/302. httpx follows HTTP redirects but not meta-refresh, so the scraper got tiny redirect pages with no `<main>` or `<article>` tags.

**Fix in `scripts/build_index.py` `fetch_html()`:** Added meta-refresh detection and follow:
```python
if 'http-equiv="refresh"' in resp.text.lower():
    match = re.search(r'url=([^"\'>\s]+)', resp.text, re.IGNORECASE)
    if match:
        redirect_url = match.group(1).strip()
        if redirect_url.startswith('/'):
            redirect_url = urljoin(str(resp.url), redirect_url)
        resp2 = await client.get(redirect_url)
        if resp2.status_code == 200:
            return resp2.text
```

### 12. Checkpoint Never Saved for Failed URLs
**Problem:** The checkpoint save logic was only inside the success branch (when a page is extracted). With ~90% of ArcMap URLs returning 404 or lacking content containers, the checkpoint was never saved, losing all progress on restart.

**Fix in `scripts/build_index.py`:** Added checkpoint saving to both failure paths (every 100 URLs):
```python
if html is None:
    failed_urls.add(url)
    done_urls.add(url)
    n = len(done_urls)
    if n % 100 == 0:
        save_checkpoint(config["checkpoint"], done_urls, pages, failed_urls)
    return
```
